Коли ви виконуєте команду генерації відповідей по всьому датасету:
```bash
uv run python -m src answer_dataset --student_search_results_path data/output/search_results/UnansweredQuestions/dataset_docs_public.json --save_directory data/output/search_results_and_answer/UnansweredQuestions
```

```bash
uv run python -m src answer_dataset --student_search_results_path data/output/search_results/UnansweredQuestions/dataset_code_public.json --save_directory data/output/search_results_and_answer/UnansweredQuestions
```

uv run python -m src answer_dataset --student_search_results_path data/output/search_results//hybrid/UnansweredQuestions/dataset_code_public.json --save_directory data/output/search_results_and_answer/UnansweredQuestions

запускається завершальний етап RAG-пайплайну: Augment & Generate (підготовка
контексту та генерація відповідей локальною мовною моделлю Qwen).

Нижче наведено послідовний ланцюжок і всі задіяні файли проєкту:

Послідовний ланцюжок і задіяні файли:

1.  src/__main__.py

      - Точка входу при виклику python -m src.
      - Передає керування бібліотеці fire.Fire(CLI).

2.  src/cli.py

      - Метод CLI.answer_dataset(...) приймає шляхи
        --student_search_results_path, --save_directory, а також шлях до індексу
        за замовчуванням --index_directory "data/processed".
      - Передає параметри у функцію run_answer_dataset(...).

3.  src/commands/answer_cmd.py

      - Головний оркестратор пакетної генерації (run_answer_dataset).
      - Зчитує JSON-файл із попередньо знайденими джерелами
        (student_search_results_path).
      - Отримує інстанс генератора через get_generator().
      - Ітерується по питаннях з індикатором прогресу (tqdm).
      - Для кожного запитання:
        1.  Відновлює текстовий зміст знайдених джерел за допомогою
            resolve_chunks(...).
        2.  Викликає модель gen.generate(...).
        3.  Упаковує результат у MinimalAnswer.
      - Зберігає фінальний результат у форматі StudentSearchResultsAndAnswer у
        файл за шляхом --save_directory.

4.  src/retrieval.py

      - Використовуються службові функції:
          - resolve_chunks(sources, index_directory): оскільки у файлі пошуку
            збережені лише координати (file_path, first_character_index,
            last_character_index), ця функція відновлює сам текст чанка.
            Спочатку вона шукає його в кеші/індексі KnowledgeBase.chunks, а якщо
            не знаходить — читає напряму з диску через
            read_file_safely(src.file_path), бо file_path
            (data/raw/vllm-0.10.1/...) є водночас дисковим шляхом відносно
            кореня проєкту.
          - err(...): безпечне логування можливих помилок у sys.stderr.

5.  src/index.py

      - Викликається всередині resolve_chunks
        (KnowledgeBase.load(index_directory)), щоб підтягнути збережені чанки з
        chunks.json і миттєво знайти оригінальний текст кожного фрагмента за
        координатами, без зайвого перечитування сотень файлів з диска.

6.  src/tokenizer.py

      - Завантажується автоматично при виклику KnowledgeBase.load(...) для
        відновлення структур індексу.

7.  src/ingest.py

      - Функція read_file_safely(path) використовується як fallback у
        resolve_chunks, якщо якогось чанка немає в оперативній пам'яті індексу —
        зчитує оригінальний файл з диска без помилок кодування.

8.  src/chunk_types.py

      - Надає dataclass Chunk для збереження та передачі тексту фрагментів разом
        із координатами у генератор.

9.  src/generator.py

      - Серце етапу Augmentation & Generation:
          - get_generator(): реалізує патерн Singleton, створюючи та кешуючи
            об'єкт AnswerGenerator.
          - _ensure_loaded(): завантажує токенізатор та ваги моделі
            Qwen/Qwen3-0.6B через HuggingFace transformers (на CUDA у float16,
            або на CPU у float32).
          - format_context(chunks): етап Augment — перетворює список чанків у
            нумерований список джерел виду: [Source i] path (start-end):\n<text>
          - build_prompt(question, context): формує системну інструкцію та
            підставляє контекст із запитанням.
          - generate(...): токенізує промпт, запускає детерміновану генерацію
            (do_sample=False, temperature=0.0) з лімітом нових токенів і декодує
            відповідь моделі без відлуння вхідного промпту.

10. src/models.py

      - Pydantic-моделі для валідації та запису результатів:
          - MinimalSource: перевіряє вхідні координати джерел.
          - MinimalAnswer: об'єднує запитання, джерела та згенеровану текстову
            відповідь answer.
          - StudentSearchResultsAndAnswer: фінальна обгортка для всього датасету
            та параметра k, яка серіалізується у результуючий JSON.

11. src/__init__.py та src/commands/__init__.py

      - Ініціалізаційні файли пакетів Python.

Файли, які НЕ беруть участь у цій операції:

  - chunk_python.py, chunk_markdown.py, chunking.py, chunk_window.py, hash.py
    (розбиття та хешування файлів потрібні лише для індексації).
  - cache.py (кешуються лише пошукові запити на етапі search, на етапі генерації
    цей файл не задіюється).
  - dense.py (семантичний пошук не використовується, оскільки джерела вже
    вибрані на попередньому кроці).
  - evaluator.py та eval_cmd.py (підрахунок метрик тут не виконується).
