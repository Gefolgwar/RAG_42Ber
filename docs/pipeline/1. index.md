
```bash
uv run python -m src index --max_chunk_size 2000
```

виконується ланцюжок викликів по модулях проєкту. Нижче наведено послідовний
список усіх задіяних файлів та роль кожного з них у цьому процесі:

Покроковий ланцюжок та файли:

1.  src/__main__.py

      - Точка входу при виклику -m src.
      - Запускає бібліотеку fire.Fire(CLI).

2.  src/cli.py

      - Клас CLI парсить аргументи командного рядка (index,
        --max_chunk_size 2000).
      - Метод CLI.index(...) делегує виконання функції run_index(...) із модуля
        команд.

3.  src/commands/index_cmd.py

      - Головний оркестратор процесу індексації (run_index).
      - Перевіряє валідність аргументів (0 < max_chunk_size <= 2000).
      - Керує процесом: знаходить файли, порівнює хеші, запускає розбиття на
        чанки, викликає побудову індексу та зберігає артефакти (chunks.json,
        hashes.json, meta.json).

4.  src/retrieval.py

      - Викликається лише функція логування помилок err(...).
      - Розташування корпусу — константа (data/raw/vllm-0.10.1), тому окремих
        функцій для розгортання вкладеності чи мапінгу шляхів немає.

5.  src/ingest.py

      - Викликаються функції:
          - collect_files(...): знаходить усі валідні файли у репозиторії.
          - iter_files(...): рекурсивно обходить дерево каталогів, ігноруючи
            технічні папки (.git, __pycache__ тощо).
          - read_file_safely(...): зчитує вміст кожного файлу в UTF-8 з
            errors="replace", щоб запобігти падінню програми на
            бінарних/пошкоджених символах.

6.  src/file_filter.py

      - Викликається з ingest.py (функція matches(...)).
      - Визначає, чи підходить файл під розширення документації (.md, .rst,
        .txt) або коду (.py).

7.  src/hash.py (підтримка інкрементальної індексації / Bonus 3)

      - Викликаються функції hashes_for(...), compute_hash(...) (обчислення
        SHA-256 вмісту кожного файлу) та diff_hashes(...) (порівняння зі
        збереженим станом із data/processed/hashes.json, щоб не чанкувати
        незмінені файли повторно).

8.  src/chunking.py

      - Фасад для розбиття файлу на чанки (chunk_file(...)).
      - Залежно від розширення направляє файл або в Python-парсер, або в
        Markdown-парсер.

9.  src/chunk_python.py

      - Використовується для всіх .py файлів.
      - Будує AST-дерево (ast.parse) і розбиває код по межах класів та функцій
        найвищого рівня.

10. src/chunk_markdown.py

      - Використовується для документації (.md тощо).
      - Шукає ATX-заголовки (#, ##, ...) і ділить текст по розділах.

11. src/chunk_window.py

      - Допоміжний модуль для чанкінгу.
      - Якщо функція, клас або розділ перевищують max_chunk_size (2000
        символів), функція split_oversized(...) розрізає їх ковзним вікном із
        перекриттям (10% overlap).
      - spans(...) формує фінальні об'єкти чанків.

12. src/chunk_types.py

      - Оголошує dataclass Chunk (file_path, first_character_index,
        last_character_index, text), в екземпляри якого упаковуються всі
        фрагменти.

13. src/index.py

      - Клас KnowledgeBase:
          - KnowledgeBase(chunks).build(): об'єднує шлях файлу та текст кожного
            чанка й будує лексичний індекс bm25s.BM25().
          - KnowledgeBase.save(...): зберігає корпус у chunks.json, параметри
            часу та кількості в meta.json, а словник і структури BM25 — у папку
            data/processed/bm25_index/.

14. src/tokenizer.py

      - Викликається з index.py (build_tokenizer()).
      - Налаштовує токенізатор bm25s (приведення до нижнього регістру,
        регулярний вираз \w+, видалення англійських стоп-слів).

15. src/__init__.py та src/commands/__init__.py

      - Необхідні пакетам Python для імпорту модулів.

(Примітка: файл src/dense.py за замовчуванням при цьому виклику не виконується,
оскільки прапорець --dense за замовчуванням встановлений у False).
