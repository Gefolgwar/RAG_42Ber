Коли ви виконуєте команду:

```bash
uv run python -m src search_dataset --dataset_path data/datasets/UnansweredQuestions/dataset_docs_public.json --k 10 --save_directory data/output/search_results/UnansweredQuestions
```

```bash
uv run python -m src search_dataset --dataset_path data/datasets/UnansweredQuestions/dataset_code_public.json --k 10 --save_directory data/output/search_results/UnansweredQuestions
```

відбувається пакетний пошук для всіх питань із заданого датасету. Ось які файли
беруть участь у цьому процесі та яку роль кожен із них виконує:

Послідовний ланцюжок і задіяні файли:

1.  src/__main__.py

      - Точка входу при виклику python -m src.
      - Передає керування CLI-інтерфейсу через fire.Fire(CLI).

2.  src/cli.py

      - Python Fire зіставляє команду search_dataset та аргументи
        (--dataset_path, --k, --save_directory) з методом
        CLI.search_dataset(...).
      - Делегує виконання функції run_search_dataset(...).

3.  src/commands/search_cmd.py

      - Головний оркестратор пакетного пошуку (run_search_dataset).
      - Завантажує індекс за допомогою load_kb(index_directory).
      - Читає JSON-файл датасету за шляхом --dataset_path і витягує список
        питань rag_questions.
      - Створює екземпляр кешу QueryCache(fingerprint=...).
      - Ітерується по питаннях з індикатором прогресу (tqdm), викликаючи пошук
        search_cached(...).
      - Формує фінальну модель StudentSearchResults і зберігає її в файл під
        --save_directory.

4.  src/retrieval.py

      - Викликаються ключові функції обслуговування пошуку:
          - load_kb(index_directory): безпечно відновлює об'єкт KnowledgeBase.
          - fingerprint(index_directory): зчитує created_at із
            data/processed/meta.json для інвалідації кешу, якщо індекс оновився.
          - search_cached(...): перевіряє наявність результатів у кеші; якщо
            промах — викликає пошук через BM25, формує MinimalSource і записує
            результат у кеш.
          - chunk_to_source(ch): конвертує знайдені внутрішні об'єкти Chunk у
            моделі MinimalSource.
          - err(...): безпечне виведення повідомлень про помилки у sys.stderr.

5.  src/index.py

      - Метод класу KnowledgeBase.load(index_directory):
          - Відновлює стан індексу BM25 із папки bm25_index/.
          - Відновлює токенізатор та його словник.
          - Завантажує чанки з chunks.json.
      - Метод kb.search_bm25(query, k, file_type):
          - Токенізує запитання.
          - Виконує скоринг документів через бібліотеку bm25s.
          - Фільтрує результати за file_type (якщо задано) і повертає топ-k пар
            (Chunk, score).

6.  src/tokenizer.py

      - Використовується об'єктом KnowledgeBase для створення та налаштування
        токенізатора (build_tokenizer()), через який проганяється текст кожного
        запитання перед запитом до BM25.

7.  src/file_filter.py

      - Викликається з KnowledgeBase.search_bm25 (функція matches(...)), щоб
        перевірити, чи відповідає знайдений файл категорії (за замовчуванням
        "all" — тобто .py, .md, .rst, .txt).

8.  src/chunk_types.py

      - Надає dataclass Chunk, об'єкти якого відновлюються з chunks.json і
        зберігаються в пам'яті всередині KnowledgeBase.chunks.

9.  src/cache.py

      - Клас QueryCache:
          - Перевіряє актуальність збереженого кешу
            (data/processed/query_cache.json) за фінгерпринтом індексу.
          - cache.get(query, k): повертає раніше знайдені результати у разі
            збігу запиту.
          - cache.put(query, k, sources): зберігає отримані результати на диск у
            JSON.
      - cache_key(query, k): генерує хеш SHA-256 від нормалізованого запиту і k.

10. src/models.py

      - Pydantic-моделі для валідації та серіалізації:
          - MinimalSource: представляє окремий чанк (file_path,
            first_character_index, last_character_index).
          - MinimalSearchResults: групує question_id, question та список
            retrieved_sources.
          - StudentSearchResults: фінальний контейнер списку результатів та
            параметра k, який конвертується у JSON через
            .model_dump_json(indent=2).


Файли, які НЕ беруть участь у цій операції:

  - generator.py та answer_cmd.py (генерація відповідей Qwen на цьому кроці не
    викликається).
  - evaluator.py та eval_cmd.py (оцінювання Recall виконується окремою командою
    або зовнішньою moulinette).
  - chunk_python.py, chunk_markdown.py, chunking.py, hash.py, ingest.py (файли
    вже розбиті та проіндексовані на етапі index).
  - dense.py (гібридний/семантичний пошук у базовому виклику search_cached має
    прапорець hybrid=False).
